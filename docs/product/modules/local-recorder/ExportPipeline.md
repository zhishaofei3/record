# ExportPipeline — 导出管线

> **模块**：[Local Recorder](index.md) | **级别**：完整 | **最后更新**：2026-05-07

## 关系

| 方向 | 类型 | 目标 | 说明 |
|------|------|------|------|
| → | 触发 | [RecordingWorkspace](RecordingWorkspace.md) | 回传路径确认、导出成功或失败状态 |
| ← | 依赖 | [RecordingWorkspace](RecordingWorkspace.md) | 由工作台在停止录制后触发导出 |
| ← | 依赖 | [BackgroundProcessor](BackgroundProcessor.md) | 需要拿到最终应写入 mp4 的视频输出 |

## 功能

在停止录制后完成保存路径确认、音视频封装、mp4 写入和自动打开导出目录。

## 界面结构

```text
[ Stop ] -> [ Save Panel ] -> [ Exporting ] -> [ Open Folder ]
```

## 不变式（必须永远成立的规则）

- 未经路径确认不得开始文件写入。
- 导出结果必须包含录制时选定的音视频配置。
- 导出完成后必须触发打开导出目录的收尾动作。

## 状态机

| 当前状态 | 触发事件 | 动作 | 下一状态 |
|---------|---------|------|---------|
| `idle` | 收到停止录制结果 | 请求用户确认保存路径 | `awaiting-path` |
| `awaiting-path` | 用户确认路径 | 开始编码和写文件 | `exporting` |
| `awaiting-path` | 用户取消 | 保持待导出或返回工作台 | `awaiting-path` |
| `exporting` | 写入成功 | 打开导出目录并回传结果 | `done` |
| `exporting` | 写入失败 | 记录错误 | **`export-error`** |
| **`export-error`** | 用户重试 | 重新请求路径或重新写入 | `awaiting-path` |

## 故障旅程

| 故障场景 | 检测方式 | 降级策略 | 恢复路径 |
|---------|---------|---------|---------|
| 用户取消保存 | 保存对话框返回取消 | 不写入最终文件并保留临时录制 | 用户重新发起导出 |
| 磁盘空间不足 | 写文件阶段失败 | 展示导出失败 | 用户释放空间后重试 |
| 编码异常 | 封装过程报错 | 展示导出失败 | 用户重试导出 |
| 打开目录失败 | 系统打开动作失败 | 保留成功文件并提示 | 用户手动定位文件 |

## 性能约束

- 停止录制后应尽快进入可见的导出进度或状态反馈。
- 成功导出后自动打开目录不能阻塞文件落盘完成确认。

## Non-Goals（刻意不做）

- 不负责云端上传和远程分享。

## 技术摘要

- 将停止录制后的收尾和写文件职责从工作台中分离。

## 已知限制

- 默认文件名采用时间戳方案，尚未提供用户自定义命名模板。
